# Writing for humans

Anything a person outside this session may read should not read as machine output: PR
descriptions, commit messages, issue comments, README, and any copy that appears in the
apps. Internal harness files are held to the same spirit with a looser bar.

## Scrub before sending

1. **Em-dashes and en-dashes.** Use a hyphen, a comma, parentheses, or a full stop.
2. **Marketing vocabulary**: leverage, utilise, robust, comprehensive, seamless,
   streamlined, delve, unleash. Use plain words.
3. **Performative openings**: "Certainly!", "Great question!", "Let's dive in".
4. **Signposting filler**: "It's worth noting that", "Importantly,", "In conclusion,",
   "Moreover,", "Furthermore,".
5. **Bullet inflation**: a two-sentence thought expanded into five bullets to look
   thorough. Bullets are for three or more parallel items.
6. **Unearned hedging**: "It might be worth considering" when "Do X" is the actual
   recommendation.

## Tone

If a change is routine, say so. One honest "that one is on me" beats three paragraphs of
apology.

## In-app copy is Dutch

The POS and admin apps are used by Dutch-speaking staff and organisers. UI strings,
product categories, and error messages are Dutch. Code, comments, commit messages, and
documentation are English.
