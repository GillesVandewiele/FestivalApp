# FestivalApp — drink-sales registration and analysis

Two front-ends over one backend: a tablet POS for bar staff during a festival, and an
analytics app for organisers. The point of the system is the dataset it leaves behind,
which is what decides next year's purchasing.

**This repository is public.** Read [`.claude/rules/public-repo-secrets.md`](.claude/rules/public-repo-secrets.md)
before touching configuration, deployment, or anything that reads an environment variable.

| Area | Path | Responsibility |
|---|---|---|
| Backend | `backend/app/` | FastAPI. `routers/` HTTP surface, `services/` business rules, `models/` Pydantic documents, `db.py` connection and indexes, `security.py` hashing and tokens |
| Backend tests | `backend/tests/` | pytest against a real MongoDB. Never a mock |

## Invariants

These are load-bearing. Breaking one silently corrupts the dataset the whole product
exists to produce. Full detail in [`.claude/rules/sales-data-invariants.md`](.claude/rules/sales-data-invariants.md).

- Order `_id` is generated by the tablet. Sync is idempotent because of it.
- Order `status` is a one-way ratchet: `confirmed` to `voided`, never back.
- `device_id` and `total_coupons` are always recomputed server-side, never trusted from the payload.
- Orders snapshot the name and coupon price they were sold at. Cost price is joined at report time.
- Product `slug` is stable across editions. It is the year-over-year join key.

## Model selection per task

Match the model to the cognitive load. Applies to `Agent` dispatches (the `model`
parameter) and as a hint when the main session is mismatched.

| Task shape | Model |
|---|---|
| Mechanical, near-zero judgment: renaming across files, formatting, a templated commit message from a known diff | Haiku 4.5 |
| Well-scoped execution where the thinking is already done: implementing one task from a written plan, writing tests for an agreed spec, "where is X defined" | Sonnet 5 |
| Design, architectural trade-offs, debugging without a hypothesis, writing or reviewing a plan, anything weighing options | Opus 5 |

The main session stays on Opus unless the user downshifts. If a Haiku or Sonnet subagent
returns hand-waving or the wrong abstraction, redo the dispatch on Opus rather than
patching the result.

## Token-frugal tool usage

Large tool output is the main way a session burns its context budget. When a command
might be chatty (test suites, builds, `grep -r` over the tree, data dumps), redirect it
to a file in the session scratchpad first, then extract what you need.

```bash
# Bad: the entire pytest log lands in the transcript
uv run pytest -v

# Good: capture once, query repeatedly
uv run pytest -v > "$SCRATCH/pytest.log" 2>&1
tail -n 40 "$SCRATCH/pytest.log"
grep -nE "FAILED|ERROR" "$SCRATCH/pytest.log"
```

Applies to `pytest`, `npm run build`, `npm test`, `find`/`grep -r` over the tree, and any
data file bigger than a screen. Skip it for things small by construction (`git status`,
a single-file read).

The scratchpad is for **regenerable output only**. Source, scripts, docs, and plans go
straight to the repository. See [`.claude/rules/no-work-in-scratch.md`](.claude/rules/no-work-in-scratch.md).

## Tooling

- **Python** via `uv`, rooted at `backend/`. See [`.claude/rules/python-uv.md`](.claude/rules/python-uv.md).
- **Tests** need a real MongoDB. `scripts/dev-mongo.sh` fetches one into `.tools/`; no Docker or sudo required. CI uses a service container.
- **`make help`** lists every target. `make check` is what CI runs.
- **Frontend** via `npm` workspaces (Node 22).
- **Deployment**: backend on Render free tier, both frontends on Cloudflare Pages, database on MongoDB Atlas M0. See [`docs/DEPLOYMENT.md`](docs/DEPLOYMENT.md).
